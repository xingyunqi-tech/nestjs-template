# M0 技术验证脚本

前端仓库 `docs/ops-import-ai-plan.md` 第 3 节「M0 技术验证」的一次性脚本，不进入正式代码。样本与标准答案见 `../samples/`。

本目录是独立的 Node 工程（ESM JavaScript，Node 22），依赖不进后端根目录的 `package.json`。

## 安装

```bash
cd scripts/poc/m0
pnpm install --ignore-workspace
```

`node_modules/` 与输出目录 `out/` 已在本目录的 `.gitignore` 中忽略。

## 运行

```bash
# 只跑阶段一（解析）与公式还原评估，不需要 LLM
pnpm parse

# 阶段一 + 阶段二（提取）+ 全部指标；没有 LLM_API_KEY 时自动跳过阶段二
LLM_API_KEY=sk-xxx pnpm start

# 只跑部分样本、调整每块题数
LLM_API_KEY=sk-xxx node src/main.mjs --samples s2,s3 --chunk-size 10
```

| 参数 / 环境变量                                                                     | 说明                                                                                          | 默认值                     |

## 流程

1. **解析**（`src/docx.mjs`、`src/pdf.mjs`）
   - docx：先用 jszip 读出 `word/document.xml`、`footnotes.xml`、`endnotes.xml`、`header*.xml`、`footer*.xml`，把每个 `m:oMath` 转成 LaTeX（`src/omml.mjs`），原位替换为内容是 `$LaTeX$` 的 `w:r`，再交给 mammoth 转 HTML；HTML 转题目文本（`src/html-to-text.mjs`），表格转 Markdown 表格，图片导出到 `out/<样本>/assets/` 并替换为 `![](assets/xxx)`。
     - 修订标记：`w:ins` 中的公式内容保留，`w:del` 中的丢弃。未覆盖的 OMML 结构输出 `\text{[?m:xxx]}`，公式内其它未知元素忽略，两者都在报告中计数。
     - mammoth 只输出正文、脚注和尾注；页眉页脚中的公式只计数并在报告中提示。
     - `o:OLEObject` 且 ProgID 含 `Equation` / `MathType` 的 OLE 公式对象无法转换，计数并在报告中提示。
   - pdf：unpdf 取文字与坐标。每页取最上、最下各 2 行作为候选，候选在其他页同一纵向位置（±3pt）出现相同文本（数字视为相同）、或最外侧一行符合页码格式时，作为页眉页脚去掉。剩余文字在页面宽度 30%–70% 的范围内按 x 方向覆盖直方图找最宽的空白带（至少 6pt），两侧文字都足够多时按空白带中线分栏；随后按行合并，再把因换行断开的句子拼回。
   - 扫描件判定：每页去掉页眉页脚后的非空白字符少于 50 记为低文字页，所有页都是低文字页才判为扫描件并拒绝；部分低文字页只在报告中逐页标记。`s3t`（s3 末尾追加一页只有「（全卷完）」的变体）只跑阶段一，用来确认短尾页不会触发拒绝。
2. **提取**（`src/segment.mjs`、`src/extract.mjs`）
   - 识别「参考答案」标题，切出文末答案区；独立答案文件（s5）整份作为答案区。
   - 题目区按连续题号切成题目单元，材料引导语（「回答 1～4 题」）归入首题，每块默认 15 题，材料组不跨块。
   - 每块调用 `/chat/completions`（`response_format: json_object`，`temperature: 0`），输出与 `expected` 同结构的 `materials` / `questions`。
   - 返回内容为空或 JSON 解析失败时原样重试一次；`finish_reason=length` 时把块对半切开分别调用，仍截断则继续对半，最多切 3 层。
   - 答案区按题号切块后单独调用，块内每题的答案与解析不拆开，对半重试时每半都带上答案区的表头。答案区有答案时优先使用，并覆盖题目块中的解析与评分要点；题目块里的答案与答案区不一致时计为冲突。
   - 单次调用失败（HTTP 错误、超时）只记录错误，不影响同一样本的其他调用与已完成调用的用量。
   - 每次调用的输入、缓存命中、输出 token、耗时、`parseError` 与错误都写入 `out/<样本>/extracted.json` 与报告。
3. **评估**（`src/evaluate.mjs`）并生成报告 `out/report.md`、`out/metrics.json`。

## 输出

| 路径                        | 内容                                 |
| --------------------------- | ------------------------------------ |
| `out/<样本>/text.txt`       | 阶段一得到的中间文本                 |
| `out/<样本>/answers.txt`    | 独立答案文件的中间文本（s5）         |
| `out/<样本>/assets/`        | docx 中导出的图片                    |
| `out/<样本>/formulas.json`  | 按文档顺序提取的公式 LaTeX（s2、s7） |
| `out/<样本>/parse.json`     | 阶段一的统计与检查结果               |
| `out/<样本>/extracted.json` | 阶段二的提取结果与每次调用的用量     |
| `out/metrics.json`          | 全部指标                             |
| `out/report.md`             | 报告                                 |

## 指标

比较前统一做规范化：NFKC（全角转半角）、去掉所有空白、Unicode 减号与各类短横线统一为 `-`、弯引号统一为直引号、图片路径忽略文件名；`$...$` 中的 LaTeX 额外去掉 `\left` / `\right`，把 `^`、`_`、`\frac`、`\sqrt` 的参数统一加花括号、去掉只包一个记号的多余花括号，并统一 `\leq`/`\le`、`\dfrac`/`\frac` 等同义命令；命令与其后的字母之间保留分隔（`\sin x` 与 `\sinx` 不等价）。

**阶段一（不依赖 LLM）**

| 指标                     | 含义                                                                                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 公式还原正确率（s2、s7） | 文档中按顺序提取的公式，与 `expected` 中按文档出现顺序排列的 `$...$` 做最长公共子序列对齐，匹配数 / 期望数，同时报告多余公式数。s2 由 `formula.py` 生成 OMML，s7 是按 Word 输出风格手写的 OMML，两者都是构造样本，结果不代表真实文档 |
| 扫描件判定               | s6 是否被拒绝；其他样本（含 s3t）是否被误判                                                                                                                                                                                          |
| 题号检出 / 顺序          | 用切块规则在中间文本里找到的题号个数，以及是否与期望题号顺序完全一致；双栏 PDF 用它检查阅读顺序                                                                                                                                      |
| 题干缺失                 | 期望题干（规范化后）不包含在对应题号文本单元中的题号                                                                                                                                                                                 |

**阶段二（需要 LLM）**，按题号与 `expected` 对齐：

| 指标            | 含义                                                                                                                                                                                           | docx 期望 | pdf 期望 |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | -------- |
| 题目切分正确率  | 该题号恰好提取出 1 道题，且题干相似度（编辑距离）≥ 0.9；漏题、并题、拆题都记为错误                                                                                                             | ≥ 98%     | ≥ 95%    |
| 题干完全一致率  | 该题号恰好 1 道题，且题干规范化后完全相等                                                                                                                                                      | —         | —        |
| 选项正确率      | 有选项的题目中，A–H 全部选项规范化后完全一致的比例                                                                                                                                             | ≥ 98%     | ≥ 95%    |
| 答案正确率      | 选择题只接受纯字母序列或用顿号、逗号等分隔的字母，比较字母集合，其他写法判不匹配；判断题统一为对/错；填空题按 `\|\|` 分空、`\|` 分同义答案（`$...$` 内不拆）比较集合；主观题比较规范化后的全文 | ≥ 98%     | ≥ 95%    |
| 答案冲突        | 题目块中的答案与答案区不一致的题数（最终以答案区为准）                                                                                                                                         | —         | —        |
| 公式正确率      | 期望各字段中的每个 `$...$` 是否出现在提取结果的同一字段中；括号内为多余公式数                                                                                                                  | ≥ 95%     | —        |
| 图片数量        | 题干中图片个数一致的比例                                                                                                                                                                       | —         | —        |
| 材料正文 / 表格 | 按题目归属找到对应材料后，引导语加正文规范化后完全相等；表格逐单元格规范化后完全相等                                                                                                           | —         | —        |
| 题目归属        | 材料题的 `materialKey` 指向对应材料且 `order` 一致，非材料题不带 `materialKey`                                                                                                                 | —         | —        |
| 题型            | 题型一致的比例，仅供参考                                                                                                                                                                       | —         | —        |
